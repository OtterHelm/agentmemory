# 2단계 요약 (ko6)

`AGENTMEMORY_TWO_STAGE_SUMMARY=true`로 활성화합니다. 기본값은 꺼짐입니다.
새 기록 묶음은 기존 통합 요약을 입력하지 않고 15분 주기로 요약합니다.
미통합 묶음 4개 또는 첫 미통합 묶음 생성 후 1시간에 통합 요약을 생성합니다.
남은 묶음도 없고 새 기록도 없으면 추가 호출하지 않습니다.

`mem:local-analysis:v1:summary-pipelines`에 기존 기준 요약, 미통합 묶음, 저장 대기 결과를 보관합니다.
기존 `mem:summaries`에는 기준 요약과 이후 업데이트를 구분하여 조합한 조회용 결과를 즉시 반영합니다.
문맥 주입은 각 묶음을 별도 예산 단위로 취급하며, 검색·확장 조회는 미통합 묶음도 제공합니다.
프로젝트·에이전트·작업 디렉터리 필터를 유지합니다. 삭제된 세션의 묶음은 조회하지 않습니다.

통합 실패는 15분 간격으로 최대 3회 시도하고 해당 세션의 새 요약 분석을 보류합니다.
원본 기록과 그래프 처리는 유지합니다. 미통합 묶음은 최대 8개까지 허용합니다.
기존 요약을 수동 변경하거나 삭제하면 자동 덮어쓰기 대신 충돌 상태로 보류합니다.
관리자 확인 없이 충돌이나 보류를 초기화하지 마세요.
성공한 API 결과는 저장 재시도에 재사용하되, 응답 수신 직후 프로세스가 강제 종료되면 중복 호출 가능성은 남습니다.

health는 `twoStageSummary`, `rollupPendingSessions`, `rollupBlockedSessions`, `rollupCalls`를 제공합니다.
사용량의 `operation`은 `delta`/`rollup`을 구분하며 기존 그래프·요약 비용 합계에도 포함됩니다.
통합 호출이 추가되므로 모든 작업량에서 비용이 줄어든다고 보장할 수 없습니다.
운영 검증에서는 처리한 기록 수, 대기 시간, 전체 입력·출력 토큰과 의미 보존을 함께 비교하세요.

이전 기록 재분석, 보류 기록 일괄 복구, 저가치 기록 자동 제외는 수행하지 않습니다.
일반 내보내기에는 최신 조회용 요약이 포함되지만 단계별 내부 복구 상태는 포함되지 않습니다.
완전한 복구에는 전체 데이터 볼륨 백업이 필요합니다.
롤백은 플래그를 끄고 ko5 이미지를 사용하며, 같은 데이터 볼륨을 유지합니다.
롤백 기간에 요약이 변경된 뒤 기능을 재활성화하면 기존 파이프라인과 충돌할 수 있으므로 관리자 점검이 필요합니다.
