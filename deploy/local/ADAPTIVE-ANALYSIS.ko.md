# 분석 실패 분류와 적응형 묶음 처리 (ko5)
<!-- Modified by OtterHelm for this custom distribution; see deploy/local/README.ko.md. -->

15분 주기, 요약 최대 40개/24,000자, 그래프 최대 5개/6,000자, 예산 차단 없음 정책을 유지합니다.

- 출력 잘림은 묶음 크기를 줄입니다. 줄어든 크기를 채운 성공 3회마다 두 배로 복구하며 단계별 상한을 넘지 않습니다.
- 형식 오류는 실패한 기록 묶음만 임시로 나눕니다. 다른 기록의 기본 처리량은 낮추지 않습니다.
- 임시 분할 대상은 완료·보류·삭제된 기록을 제외하고 처리합니다. 원문을 삭제하거나 완료 지문을 초기화하지 않습니다.
- 오류 발생 시 성공 연속 횟수는 초기화합니다. 기존 보류 기록을 자동 재분석하지 않습니다.
- 상태의 선택적 `successStreak`와 `isolation` 필드로 재시작 후에도 진행을 유지합니다. 추가 KV 범위는 없습니다.
- 실패 응답에는 `failureCode`만 추가 저장합니다. 제목 누락, 본문 누락, 20자 미만 본문, 스키마 오류를 구분합니다.
- 공급자 오류 본문은 저장하지 않습니다. HTTP 상태·타임아웃 등 허용된 오류 코드로 바꿉니다.
- health의 `adaptiveBatching`과 `failureCounts`로 적용 여부 및 이후 실패 분포를 확인할 수 있습니다. 과거 미분류 실패는 `legacy_unspecified`입니다.

본문 검증을 완화하거나 추론 모드·출력 한도를 변경하지 않습니다. 과거 응답 원문이 없으므로 기존 형식 실패의 정확한 원인은 미확정이며, 새 진단 코드로 후속 확인해야 합니다.

모의 응답으로 100개 기록을 성공 처리한 회귀 시험은 기존 1개 제한의 100회 대신 16회 호출합니다. 실제 토큰·비용·요약 품질 개선율을 보장하는 수치가 아닙니다.

배포 전 백업을 만들고 기존 볼륨을 유지합니다. 롤백은 ko4 이미지로 교체하며 볼륨을 삭제하지 않습니다. 공개본에는 운영 경로·키·기억 원문·실제 세션 식별자를 포함하지 마세요.
